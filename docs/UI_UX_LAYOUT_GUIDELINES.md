# UI/UX 레이아웃 가이드

## 목적

이 앱의 화면은 가운데 정렬된 `main` 컨테이너를 하나의 시각적 작업 영역으로 사용한다. 이후의 모든 UI/UX 수정은 이 영역 밖으로 콘텐츠나 조작 요소가 튀어나가지 않도록 구현한다.

커뮤니티 화면의 기준 컨테이너는 다음과 같다.

```html
<main class="community-surface mx-auto w-full max-w-md px-4 pb-28 pt-6 sm:max-w-xl">
```

- 기본 화면: `max-w-md` 안에서 표시한다.
- `sm` 이상 화면: `max-w-xl` 안에서 표시한다.
- 좌우 여백은 `px-4`를 기본값으로 사용한다.
- 카드, 입력창, 탭, 빈 상태, 오류 메시지, 목록은 기본적으로 `w-full`을 사용해 컨테이너 내부 폭을 따른다.

## 필수 규칙

1. 일반 콘텐츠는 `main`의 내부 폭을 기준으로 배치한다. `w-screen`, 화면 기준의 음수 마진, 화면 전체 폭을 강제하는 CSS는 사용하지 않는다.
2. 플로팅 버튼, 퀵 메뉴처럼 `fixed`를 쓰는 요소도 화면 우측이 아니라 컨테이너 우측에 맞춘다.
3. 모달과 드로어는 배경 오버레이만 화면 전체를 사용할 수 있다. 실제 패널은 컨테이너와 같은 최대 폭을 지키고 가운데 정렬한다.
4. `absolute` 요소는 가능한 한 해당 카드나 섹션을 `relative`로 지정한 뒤 그 내부에 배치한다.
5. 모바일 가로 스크롤이 필요한 탭·칩 목록은 컨테이너 안에서만 스크롤한다. 스크롤 영역이 문서 전체의 가로 오버플로를 만들면 안 된다.
6. 새 화면을 만들 때도 각 페이지의 `main`에 같은 폭 규칙을 명시한다. 다른 화면의 컨테이너 폭을 임의로 넘어서는 UI를 추가하지 않는다.

## 고정 버튼 구현 패턴

`fixed right-*`처럼 뷰포트 가장자리에 직접 붙이는 방식은 사용하지 않는다. 대신 전체 폭의 고정 래퍼 안에 기존 컨테이너 폭과 같은 정렬 래퍼를 두고, 버튼을 그 안에서 오른쪽 정렬한다.

```html
<div class="pointer-events-none fixed inset-x-0 bottom-5 z-30">
  <div class="mx-auto flex w-full max-w-md justify-end px-4 sm:max-w-xl">
    <button class="pointer-events-auto size-14 rounded-full">글쓰기</button>
  </div>
</div>
```

- 바깥 래퍼는 위치만 담당한다.
- 안쪽 래퍼는 페이지 `main`과 같은 `max-w-md sm:max-w-xl px-4`를 사용한다.
- 실제 버튼은 `justify-end` 안에 있으므로 컨테이너의 오른쪽 경계 안에 유지된다.
- 하단 고정 요소가 있을 때는 `main`의 `pb-*`를 충분히 확보해 마지막 콘텐츠가 가려지지 않게 한다.

## 모달 구현 패턴

```html
<div class="fixed inset-0 z-40 bg-black/40 p-4">
  <section class="mx-auto max-h-full w-full max-w-md overflow-y-auto sm:max-w-xl">
    <!-- 모달 내용 -->
  </section>
</div>
```

배경은 화면을 덮을 수 있지만, 모달 내용은 `main`과 같은 최대 폭을 넘지 않는다. 데스크톱에서 더 넓은 작성 폼이 꼭 필요한 경우에도, 해당 페이지의 `main` 폭을 먼저 함께 조정하고 이유를 기록한다.

## 수정 전 점검 목록

- 새 UI가 `main`의 좌우 경계 안에 보이는가?
- `fixed`, `absolute`, 모달, 드롭다운, 툴팁이 컨테이너 밖으로 나가지 않는가?
- 모바일에서 가로 스크롤바가 페이지 전체에 생기지 않는가?
- `sm` 이상에서도 `max-w-xl`보다 넓어지지 않는가?
- 하단 고정 UI가 콘텐츠나 모바일 브라우저 영역을 가리지 않는가?

## 예외

전체 화면을 덮는 dimmed 배경, 토스트의 접근성 알림 영역처럼 화면 전체가 필요한 비시각적 보조 요소만 예외로 한다. 이 경우에도 사용자가 실제로 조작하는 패널·버튼·카드는 컨테이너 안에 둔다.
